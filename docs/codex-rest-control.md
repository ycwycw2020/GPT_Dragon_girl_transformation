# 让 GPT_Dragon_girl_transformation 安心休息 ☾

**v1.0.0 · 没有倒计时的休息，与真实新任务联动。**

右键桌宠或托盘图标，选择 **休息**。她会换成闭眼睡姿，呼吸与摆腿更轻；不会在 60 分钟后自行恢复。休息状态保存在本地，重启桌宠后仍然有效。

## 什么时候醒来

| 情况 | 行为 |
| --- | --- |
| 右键选择“回到工作状态” | 立即手动唤醒，并恢复自动跟随任务与额度 |
| 休息之后新提交一轮任务，且全局生命周期或 Hooks 确认新的任务开始 | 自动唤醒 |
| 原来运行中的任务继续调用工具、更新日志或改变时间 | 保持休息 |
| 旧任务在重启后重新出现、状态过期或不完整 | 保持休息 |
| 点击睡着的角色 | 简短困倦反馈，不奖励经验，不启动日常互动动画 |
| 到达早午晚问候时段 | 保持休息，不自动问候 |

唤醒依赖实际确认的任务开始信息。全局生命周期或 Hooks 均无法提供完整状态时，自动唤醒不可保证；手动唤醒始终可用。程序只保存用于辨别新任务的散列标识和开始时间，不读取问题正文。新任务可来自同一 Codex 用户数据目录下的其他项目位置，不限桌宠安装目录。

## 休息会停止 Codex 的任务吗？

**当前不会。休息仅改变 GPT_Dragon_girl_transformation 的状态，Codex 的任务仍可能继续运行。**

程序会显示：

> 当前只能让 GPT_Dragon_girl_transformation 休息；无法停止 Codex 中正在运行的任务，请在 Codex 中手动停止。

休息期间，右键菜单也会保留任务未停止的提示。需要暂停工作时，请到 Codex 原界面停止相应任务。

已经调查过的本机接口目前不能可靠连接到 Codex 桌面正在运行的全部任务。新启动一个独立服务只能看到存储记录，不能证明获得了原有运行任务的控制权。因此本版将该能力明确记录为 **不可用**，不会假装“全部停止”，也不会通过杀死或挂起 Codex 进程来代替正常停止。

供维护者核验：`codex-rest-control.mjs` 返回 `supported: false`、`status: unavailable`、`scope: pet-only`、`allStopped: false`。未来只有接入经过验证的现有任务控制通道后，才会将停止能力改为可用。

## 与任务气泡的关系

电脑上方的粉白任务气泡只显示 Codex 当前正在做什么。即使 GPT_Dragon_girl_transformation 已睡着，气泡仍可能显示原任务的实际进展，这表示 Codex 仍在工作，不表示休息失效。

“我有新的提问(｡･∀･)ﾉﾞ”是独立的提问提醒，具体回答与权限审核仍在 Codex 原界面处理。休息不会自动回答或批准请求。

本版已移除陪玩入口，右键菜单保留休息、回到工作状态、好感成长和新建 Codex 聊天等功能。
